# data/

**Everything in this folder is synthetic.** No real visitor, sponsor, company or booking exists behind any row.

- `events.jsonl`: one event per line (`ts`, `type`, `variant`, `session`, `props`). Before the
  launch on 2026-08-19 every event is from the current site, so `variant` is `baseline`. From the
  launch on, the formats page and the inquiry page are those of the shipped variant, `format-quiz`.
  Home and sponsor preparation stay `baseline`.
- `inquiries.csv`: one row per submitted inquiry. `sponsor_type` is a synthetic attribute that no
  event carries. `scoping_call_booked` and `booking_confirmed` show the state on the export date.
  For `format-quiz` rows, `quiz` says whether the inquiry came through the quiz. `quiz_answered` and
  `quiz_unsure` count its questions with an answer and with "I don't know yet". `quiz_roles`,
  `quiz_stand` and `quiz_before` hold what the sponsor ticked on questions 1, 3 and 4.
- `*-live.jsonl`: written by the running site, git-ignored.

The data cover 26 weeks before the launch, from 2026-02-18, and 8 weeks after it. The last visit is
from 2026-10-13; scoping calls and bookings are counted up to 2026-10-18. The result is read after that window. Every
date inside `discovery/` follows this timeline; commit dates only show when the repo was built.

The numbers are small on purpose: a few inquiries a week, as for a small academy. Read them as an
illustration of how a funnel is counted, never as evidence about real sponsors.

A `session` is one visit. A visit can see several pages, one `page_view` each. A visit that opens
the inquiry page first sees one to three of the home, formats and sponsor preparation pages.
It opens the inquiry page once, as its last page view. Its form events happen there.
Other visits see one to three of these pages and never reach the inquiry page.

After the launch, a visit can take the quiz on the formats page. Each quiz question passed logs an
`inquiry_step_completed` with `step` 1 to 4, `answered` and `unsure`. A visit that takes the quiz
opens the inquiry page right after it. Some visits leave the quiz before the end and never reach the
inquiry page. `inquiry_submitted` carries `quiz: true` or `false`.

`events.jsonl` and `inquiries.csv` are generated by `scripts/generate-events.js` from
`scenario.json` (seeds, launch date, traffic, step rates, sponsor mix, browsing paths, quiz; it
carries `"synthetic": true`). Regenerate with `npm run generate`: same seeds, byte-identical files.
The weeks before the launch are the same as in the baseline export at the start of the training.
Change the scenario, never the generated files.

`followup_answered` comes 28 to 31 days after that visit's `booking_confirmed`. Its prop
`weeks_after: 4` counts weeks after the booking. The data hold no training date, so they cannot say
how long after the training an answer came.
